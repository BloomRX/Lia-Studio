# Lia Studio — abertura local de editores Unity e Unreal (capacidade parcial)

**Estado:** código e testes offline presentes; **Windows/engines reais NÃO EXECUTADOS nesta rodada**. Esta capacidade **abre somente o editor**: não executa build, importação verificável, jogo, testes, Agent Runtime ou QA. Não define versão mínima de Unity/Unreal nem migra projetos automaticamente. O projeto deve ser seu ou ter autorização explícita para abrir. Faça backup antes de confirmar: um editor pode executar scripts/plugins e alterar/migrar arquivos.

Em Configuração do projeto, escolha separadamente Unity ou Unreal, informe o caminho **absoluto local** do executável `Unity.exe`, `UnrealEditor.exe` ou `UE4Editor.exe` e do descritor `ProjectSettings/ProjectVersion.txt` ou `*.uproject`. Clique em **Conferir e salvar seleção** (leitura estática) e depois em **Abrir editor**; são confirmações diferentes. Task é opcional. Não baixa nem instala engines, plugins ou dependências. Não procura versões na PATH. O nome do executável só é uma verificação superficial — não é assinatura nem prova de autenticidade. O Dev deve confiar no binário e no projeto.

A API em `editor-runs` exige servidor **escutando e acessado pelo loopback**. A seleção é salva em `editor_config.json` com revisão; cada início revalida revisão, caminhos canônicos locais (sem UNC, symlink/junction), executável existente e hash/tamanho do descritor. O processo é criado no **Windows apenas**, via supervisor Job Object já usado pela Godot, sem shell e com argumentos fixos: Unity usa `Unity.exe -projectPath <pasta do projeto>`; Unreal usa `UnrealEditor.exe <arquivo.uproject>` ou `UE4Editor.exe <arquivo.uproject>`. Não aceitar flags livres nem instruções do descritor. A comparação pré-início reduz mudanças entre checagens, mas **não elimina todas as corridas de filesystem**. O Job Object supervisiona filhos/cancelamento; não restringe filesystem, rede, scripts, credenciais ou modificações do jogo. Não é sandbox.

O Studio grava `editor_runs.json` com início/estado/resultado e agrega a execução em Histórico de execuções. Logs locais são limitados e linhas que parecem conter segredos são omitidas por padrão heurístico (não garante filtrar qualquer segredo); editores GUI podem não escrever stdout/stderr relevantes. Consulte logs do próprio editor **no PC, sem publicá-los** para diagnosticar. `exit_zero` significa somente código de processo zero; `validation_status=not_run` e nenhum gate/Task/QA é promovido. Cancelar o Job Object pode perder trabalho não salvo. Interrupção do Studio antes da persistência deixa estado desconhecido, nunca sucesso. `run_history.json` pode vincular arquivo de evidência **somente dentro do projeto do Studio**, com revisão humana independente; o descritor externo aparece com hash e integridade atual, não como QA aprovado.

### Aceite pendente no Windows do Dev

1. Checkout limpo desta branch; rode `Studio-Windows-Evidence.bat --no-publish` para a suíte (não abre engines). Reveja o JSON local, sem logs brutos ou segredos.
2. Use uma cópia **descartável e com backup** de um projeto Unity e outra Unreal com binários legítimos instalados pelo Dev. Na UI local, confirme separadamente seleção e abertura. Teste revisão obsoleta, caminho ausente/junction, segundo lançamento, saída, cancelamento e fechamento com filhos. Registre versão real, resultado, arquivos alterados e se o editor abriu/importou corretamente; **não infira compatibilidade só pelo descritor**.
3. Somente depois de verificar abertura com evidência e consentimento, desenhar/implementar capacidades distintas de importar, rodar, testar e fazer build por engine/versão (inclusive versões antigas). Nenhuma dessas capacidades é entregue aqui. Agent Runtime e publicação dependem de contratos e testes separados.

Testes sem engine: `python verify_alpha.py --part 8`; todos os blocos devem rodar **separadamente**. Os testes com supervisor falso verificam argv, reversão/cancelamento, concorrência, histórico e bloqueio em preview de rede, **não** funcionamento do editor no Windows.
